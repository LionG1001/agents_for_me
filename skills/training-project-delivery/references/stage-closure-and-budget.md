# 阶段收尾、日志审查与探索预算

适用于用户要求关闭某阶段、复盘交付，或需求尚模糊但需估算训练资源的场景。固定项目路径、设备、版本、数字留在该项目，不沉淀为跨项目默认值。

## 阶段收尾

- 回读当前需求与用户最新授权。关闭阶段只匹配该阶段验收范围，不连带关闭精度、恢复或长跑任务。Jira状态以操作后的回读为准。
- 将“本地源码=实际执行版本”“已提交/推送”“等同上游最新版本”分别取证。认证失败时保留限制，仍整理可review的diff、同步清单与启动入口，不擅自发布。
- 给一条用户实际可敲的推荐入口，集中预检、唯一run目录、启动、状态和证据检查；复用已验证脚本。文档和wrapper默认值一致，区别裸配置默认与实际override。
- 新入口至少实际验证CLI、预检与拒绝条件；未执行其启动分支时明确说明。复用旧训练证据须说明数学/训练配置未变，以及新增入口的独立验证范围。
- 从零文档分清基础镜像、工作容器、外置venv/wheel库、最终发布镜像。写清资产交付前提、平台架构、digest、离线安装、挂载和执行位置。安装拒绝覆盖现有环境；隔离新环境的导入测试不冒充新环境完整训练验收。
- 工时、评论、附件和状态变更分别遵守授权；实际工时不能从GPU运行时长推造。用户说本轮不登记时继续技术工作并保留本地记录。

## loss与warning结论

1. loss先说明记录粒度、rank、梯度累积、权重方式及缺失/非有限值，避免把交错的多rank日志当全局序列。用可复算的初末窗口、来源分组和图表回答是否下降。
2. 样本/token构成、噪声、warmup、重复数据和hold-out条件与趋势一起呈现。有限loss、短期下降、收敛、泛化和精度对齐各需不同证据。
3. warning按实际调用模块、dtype/shape、发出版本、首次/末次位置和次数分类。API名、安装包名、后端候选、实际kernel命中、性能占比分开判断。
4. 非致命告警仍可能影响速度；用trace或独立探针核对实际backend和时间占比，再做数值/性能A/B。不能仅为去警告改变attention语义，也不全局屏蔽未知告警。
5. 指出看哪些日志、每个退出码/保存回读检查什么；告警次数不等于算子调用次数，启动成功不等于验收。

## 探索训练资源预算

- 分开估算下载/转换与GPU训练。原始TB不是训练样本数；记录有效图数、帧数、窗口/stride、相机、分辨率/token、来源份额和遍历目标。
- 动态packing/循环loader按每来源实测draw和唯一key覆盖建账；`max(来源数量/来源每步draw)`只是draw数量等价，不是唯一遍历保证。没有有限epoch/数据位置恢复时明确缺口。
- 没有客户目标时继续给分阶段情景：当前规模、若干固定step、扩容来源。使用`初始化 + steps×稳态时间 + 保存次数×保存时间`，再标明排期余量、checkpoint保留/写入空间、CPU/RAM/I/O和多跳传输。
- 部分参数SFT、全参、LoRA各自说明支持情况、实际trainable params和待测成本；不按参数量线性缩放时间，也不未经实测承诺全参显存或多机效率。
- 发布可复核的假设与计算结果，列出敏感性和下一小批校准实验。估算不自动授权新增TB下载、换环境或启动数天训练；已有执行授权则按约定推进，不逐轮重复询问。

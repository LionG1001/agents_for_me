# Jira收口、附件、工时与评测移交

用于训练项目结果登记、日志附件、工时补记、阶段关闭、评论精简和后续评测任务。具体工单、日期、机器与测试数字留在项目记录，不固化进skill。

## 登记范围

先结合用户指令、会话和本地记录确认目标工单及本轮要写入的内容。评论、附件、工时、描述和状态按各自授权执行；“技术工作完成”不自动表示可以关闭Jira，“上传日志并说明结果”也不包含登记工时。已有明确授权继续有效，不为同一步骤反复询问。浏览器当前显示的工单只能辅助消歧，不能替代明确指定的目标。

## 工作成果与证据分层

- Jira评论先说完成了什么、结果如何，再给关键数字和附件入口，用同事能直接读懂的语气。通常一段或少量要点足够；不把操作流水、工具调用和整段排障时间线搬进去。失败记录保留故障结论、影响和下一步。
- 性能评论保留模型/数据、设备规模、关键配方、固定计时窗口、单位和比较方向。使用真实运行记录复算；“开箱性能”说明是原始上游还是适配后工程的默认配方，不能把已有编译/Flash等默认能力算成本轮新增优化。软件栈或输入不同的跨平台结果保留这一限制，不写成固定输入精度或硬件极限结论；细节按[验收与性能口径](acceptance-and-performance.md)处理。
- 逐rank账本、源码清单、API回执和完整审计留在本地报告或附件。影响结论的限制仍用短句保留，例如估算非实测、结构检查非恢复验证。
- 用户要求精简旧评论时，先保存原文，核对作者和最近更新时间，再改写授权范围内的评论；保留有用的用户短评。发现并发编辑先重读，不能覆盖用户刚改的内容。
- 用户调整数据集、规模或阶段目标后，关闭说明写明调整后的范围和交付内容，不把未执行范围写成通过。仍需要的工作明确由哪个后续任务承接。

## 日志与附件

- 按平台/运行ID选择与结论对应的原始日志、命令、实际训练配置、计时账本和验收摘要；历史基线标明日期和版本，不混入另一轮日志。默认优先轻量材料；checkpoint、权重、视频、缓存和完整环境变量仅在用户要求且适合接收方时纳入。
- 原始日志保持不变，整理说明另写；ZIP内提供简短说明，指出运行身份、主要文件、统计窗口及已验证范围。含不同窗口的旧摘要时，明确本次比较采用哪一份。检查凭据/完整环境转储和不必要的个人信息，保留诊断所需错误与警告。
- 远端补收只读取目标运行的明确文件，核对大小或hash。打包前核对成员，完成后检查可解压及关键文件一致性。附件清单保存在项目证据区，不为整理材料新增训练或修改运行环境。
- 先读工单现有附件，避免重复上传。工具只接受服务端可读路径时，按工具文档将用户已授权的文件复制到支持的上传暂存目录，或使用支持的base64入口；不关闭路径校验，不用软链接绕过范围限制。附件限制、暂存根目录和认证位置从当前工具/组织文档读取，不写死某台机器路径。
- 不能只看“更新成功”或顶层`success=true`：逐文件检查`uploaded`和`failed`。部分失败时先核对实际已上传项，再只处理缺失项；上传结果不明时先回读，不重传整批。上传后核对名称、大小、可访问链接；必要时下载校验。评论引用实际返回的附件链接，不能以本地路径代替收件人可访问的附件。

## 主动工时与按日补差额

- 明确登记人、工单、日期、时区，以及用户给的是追加量、当天总计还是补到某个目标。“昨天/今天/两天”按用户会话时区落实到具体日期，不能取执行主机时区或沿用旧任务日期。
- 工时依据用户确认的主动工作量，覆盖代码review、实现、排障、分析和文档等实际工作；训练等待、GPU小时和人力工时分开。训练日志的起止时间不能反推出人的投入；缺少日期、工时或口径且会影响记账时，集中询问缺项。
- “填满/补满”不自动等于每天8小时。确认目标及汇总范围是当前工单还是个人跨工单当日总计；只统计相应登记人的记录，不把其他人的工时相减。“另加2小时”“今天合计2小时”“补到8小时”是三种不同操作。
- 写入前读取范围内已有worklog，按当地日期汇总秒数。补差额使用`max(0, 目标工时 - 已登记工时)`；例如明确目标8小时、已有5小时4分，只补2小时56分。已有量达到或超过目标时不再追加，不自行删改既有条目。新增review时间也只记一次，不能同日跨任务重复计算。
- 评论简述当日实际工作和结果，不填训练等待或虚构细分时段。若按日汇总借用统一开始时刻，说明该时刻仅作日期归属，不声称连续工作了该时段。写入后回读新增ID、日期、秒数和工作说明，并复算当天总计；保留其他日期和未授权修改的记录。

## 状态流转与写入核验

- 获得关闭/状态变更授权后，先读可用transition，再执行并独立回读实际状态、resolution和剩余工作。操作名可能与目标语义不同，例如CLOSE可能落到“非问题”；不能仅凭成功响应宣称正确关闭。映射不符时沿已授权目标的可用路径纠正，不擅自修改项目工作流。
- 描述、评论、附件、工时和状态分别核验。请求超时或返回内容不清时先读实际状态；不盲重试，以免重复评论、附件或工时。回执保留工单、条目ID/链接和核验结果即可，认证信息不得进入项目证据。
- 收尾只报告本轮实际写入项和链接。评论已发布不等于工时已登记，附件上传不等于任务已关闭；未执行项如实说明。

## 从训练跑通移交模型验收

| 层级 | 对应工作与证据 |
| --- | --- |
| 训练与性能 | 数据读取、参数更新、正常退出、保存/恢复及同口径吞吐 |
| 精度对齐 | 同源码/初始权重/输入和随机设置/优化器与batch合同下的loss、梯度或参数误差，明确参考与容差 |
| 权重效果 | 确认导出与加载正确，固定评测集和推理配置，对比基座、参考训练权重与目标权重的任务指标及输出样例 |

后续工单写清参考结果、评测数据、指标/阈值、权重身份、脚本和复现命令。尚无阈值时把确认它作为执行前工作，不编造通过标准。有限loss或吞吐提高不能替代效果评测；只要求更新工单时，不扩展为实际训练或评测启动。

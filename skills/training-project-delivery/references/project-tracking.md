# Jira收口与评测移交

用于训练项目阶段关闭、工作日志、评论精简和后续评测任务。具体工单、日期、机器与测试数字留在项目记录。

## 工作成果与证据分层

- Jira评论回答做了什么、得到什么结果、是否影响本工单验收。通常一段或少量要点足够；性能保留必要的规模、GBS、计时口径和关键结果。失败记录保留故障结论与处理动作，不搬入整段排障时间线。
- 逐rank账本、源码清单、API回执和完整审计留在本地报告或附件。影响结论的限制仍用短句保留，例如估算非实测、结构检查非恢复验证。
- 用户要求精简旧评论时，先保存原文，核对作者和最近更新时间，再改写授权范围内的评论；保留有用的用户短评。发现并发编辑先重读，不能覆盖用户刚改的内容。
- 用户调整数据集、规模或阶段目标后，关闭说明写明调整后的范围和交付内容，不把未执行范围写成通过。仍需要的工作明确由哪个后续任务承接。

## 工时与状态

- 先读已有日志，按用户确认的日期、主动工作量登记，补差额时避免重复。人力工时、GPU小时、训练等待分别记录；缺少工时数时询问，不沿用上一次日期的全天时长。按日汇总的起始时间只表示日期归属。
- 读取可用transition后执行，并独立回读实际状态及完成原因。操作名可能与目标语义不同，例如CLOSE可能落到“非问题”；不能仅凭成功响应宣称正确关闭。映射不符时沿可用路径纠正，不擅自修改项目工作流。
- 描述、评论、工时和状态分别回读。写入结果不明时先查实际状态，避免盲目重试造成重复条目；保留其他日期已确认记录。

## 从训练跑通移交模型验收

| 层级 | 对应工作与证据 |
| --- | --- |
| 训练与性能 | 数据读取、参数更新、正常退出、保存/恢复及同口径吞吐 |
| 精度对齐 | 同源码/初始权重/输入和随机设置/优化器与batch合同下的loss、梯度或参数误差，明确参考与容差 |
| 权重效果 | 确认导出与加载正确，固定评测集和推理配置，对比基座、参考训练权重与目标权重的任务指标及输出样例 |

后续工单写清参考结果、评测数据、指标/阈值、权重身份、脚本和复现命令。尚无阈值时把确认它作为执行前工作，不编造通过标准。有限loss或吞吐提高不能替代效果评测；只要求更新工单时，不扩展为实际训练或评测启动。

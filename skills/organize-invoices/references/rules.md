# 发票整理规则

## 规则优先级

依次执行：

1. 用户明确给出的日期范围和本轮要求。
2. 唯一原件保护和重复票安全。
3. 类别合规和每日金额上限。
4. 用户要求最大化收益时，优先最大化本轮可报销计入总额。
5. 正好达到上限的日期数，其次是接近上限的日期数。
6. 开票日期与出差日期接近。
7. 文件数量、命名稳定性和报告简洁性。

不得用低优先级目标破坏高优先级规则。

## 目录结构

```text
工作目录/
├── 未整理/                         # 新收到、尚未入库的原件
├── 原始发票/                       # 每个发票号码一份权威原件，含交通票
├── 交通/                           # 可选交通工作副本，不参与餐补
├── 已报销发票台账.csv               # 跨周期防重复使用台账
└── 整理结果_<开始>至<结束>_第N次/
    ├── YYYY-MM-DD/                 # 当日入选发票工作副本
    ├── 超150元待单独处理/           # 超限额工作副本
    ├── 跨日平均发票/                 # 每张跨日大额票只保存一份工作副本
    ├── 下一次报销待整理/            # 本轮未入选的合规工作副本
    └── 整理清单.md
```

同一日期范围编号最大的结果默认为活动结果。重新整理时默认把活动结果更名为下一编号并原地重排；旧结果默认只保留清单，除非用户明确要求保留 PDF 快照。

## 权威原件和重复票

- 以 `原始发票/` 为唯一原件来源。
- 原件字节必须保持不变，必要时用 SHA-256 核对。
- 业务重复只按 20 位发票号码判断，不能按金额、商家、日期或文件名推断。
- “除重复票外保留所有原件”指每个发票号码保留一份未经修改的物理 PDF。
- 同号原件须核对关键字段，优先比较哈希；保留一份后才可删除冗余原件。
- 同号但日期、金额、购销方或其他关键字段冲突时不得自动删除，转人工复核。
- 文件名冲突时不得覆盖。能可靠识别号码时以发票号码作为前缀生成稳定名称；不能识别时转人工复核。
- 结果副本是派生文件。原件去重只检查 `原始发票/`；结果核验另行确认同一号码只使用一次。
- 如果用户要求整个工作区每个号码只能存在一个 PDF 路径，应先确认改用清单或文件链接，而不是复制 PDF。
- 如果当前没有 `原始发票/`，但结果目录仍有唯一副本，先选取每个号码的一份副本重建权威档案并核验哈希，不得先清理结果。

## 合规类别

默认合规：

- 饭店餐费、餐饮服务；
- 报销政策接受的外卖食品和饮料；
- 项目行或关联证据能证明属于餐食/外卖的包装费和配送费。

默认不合规：

- 出租车、网约车、客运、行程单及其他交通费用；其权威原件仍需保留；
- 普通物流、果蔬食材、无关商品，除非用户明确批准；
- 购方不符；
- 字段不可读或类别有歧义。

单张超过每日限额的发票默认不得自动分配或拆分。用户明确批准后，允许以下只影响台账、不修改 PDF 的处理：

- 略超票按每日上限计入，同时记录票面金额和计入金额。
- 大额票按 `ceil(票面金额 / 每日上限)` 个连续自然日平均分摊；用户批准时可包含周末。最后一天调整分币尾差，使分摊合计严格等于票面金额。
- 跨日票只在 `跨日平均发票/<开始>至<结束>/` 保存一份 PDF，台账只保留一条主记录，逐日金额写入整理清单，避免同号 PDF 和台账主记录重复。
- 用户未给“略超”和“大额”的数值边界时，只自动处理明显无歧义的票；边界附近转人工复核。当前明确示例为 152.00 元按 150.00 元计，497.01 元按大额跨日平均。

## 工作日和日期

- 首次整理前取得精确日期范围；用户已给出时直接执行。
- 默认周一至周五。法定节假日或调休影响结果时另行确认或核验。
- 允许空白工作日。
- 开票日期接近默认为软优化；用户明确要求硬约束时才作为硬规则。
- 多数发票在出差结束后开具时，必须说明晚开票发票被匹配回出差日期。

## 跨周期台账

- 用 `已报销发票台账.csv` 记录：发票号码、金额、报销范围、分配日期、结果目录和状态。
- 新报销周期不得再次使用状态为“已最终报销”的号码。
- 同一范围重新整理时，可撤销该活动结果的“临时分配”记录后重算；不得撤销其他已最终报销周期。
- 用户确认报销完成后，把本轮入选号码状态更新为“已最终报销”。
- 台账缺失或状态不明确时，先汇总潜在重复风险，不得假设历史原件均可再次使用。

## 组合目标

金额统一转换为整数分。每个候选日期满足 `0 <= 当日合计 <= 每日上限`。

用户要求最大化收益时依次优化：

1. 最大化本轮可报销计入总额。
2. 最大化当日合计正好等于上限的日期数。
3. 最大化其余落入接近上限区间的日期数。
4. 最小化开票日期与分配日期的距离。
5. 最小化文件数量。

用户未给容差时，默认 `148.00 <= 当日合计 <= 150.00` 元，并在清单中说明。宁可让日期为空，也不要只为消耗发票而创建低金额日期。未能改善前述目标的发票结转到 `下一次报销待整理/`；权威原件继续保留在 `原始发票/`。

总缺口默认按 `工作日数量 × 每日上限 - 本轮全部计入总额` 计算。跨日大额票的周末分摊计入本轮总额，但不增加工作日理论额度；用户另有口径时服从用户。

## 核验清单

- 每个结果 PDF 都能识别发票号码和金额。
- 同一号码未出现在两个日期目录。
- 每张入选票只计入一次。
- 每日合计不超过上限。
- 每个结果副本均能映射到同号权威原件；预期字节相同时哈希一致。
- 整理后每个唯一号码仍有权威原件。
- 只有已确认的重复原件可以删除。
- 交通票没有进入餐饮日期目录。
- 本轮发票号码没有与其他“已最终报销”周期的台账记录冲突。
- 超限额和结转目录符合预期。
- 略超票的票面金额与计入金额遵循批准口径；跨日票日期连续、周末使用已获批准、分摊合计等于票面金额且同号 PDF 只有一份跨日工作副本。
- 清单总额与 PDF 重新提取结果一致。

## 必须报告

- 日期范围和工作日假设；
- 每个已填日期的金额与缺口；
- 所有空白工作日；
- 当前周期总缺口；
- 结转发票数量和金额；
- 超限额发票数量和金额；
- 排除或待复核文件；
- 重复票删除情况；
- `原始发票/` 的保留和核验状态。

# 项目与实验记录模板

仅在建立项目规则、记录复杂实验或完成交接时读取。所有字段都应来自用户或现场只读核验；用当前真实值替换方括号内容，删除不适用项，不保留看似真实的示例值。

## 项目级 AGENTS.md 母版

根据当前项目裁剪到约 100～150 行。已有 `AGENTS.md` 时，先识别冲突并报告；只有用户要求采用本工作模式时才合并或替换相应规则。

```markdown
# [项目名称] 本地 Git 与远端执行规则

## 适用范围

- 任务目标：[当前目标]
- 允许修改：[文件、目录或 symbols]
- 默认排除：[数据、模型、日志、缓存、checkpoint、构建产物等]
- 本文件最后核验：[YYYY-MM-DD HH:MM 时区]

## 项目身份

| 项目项 | 当前权威值 |
| --- | --- |
| 本地项目根目录 | [唯一绝对路径] |
| 本地源码仓库 | [单仓库，或外层/内层仓库及关系] |
| 本地基线 | [branch + commit] |
| 代码托管平台 | [URL，或无] |
| 远端连接方式 | [SSH / Docker / Kubernetes] |
| 远端同步路径 | [宿主机或共享存储绝对路径] |
| 容器/Pod 内运行路径 | [绝对路径] |
| 构建和测试命令 | [当前实际命令] |
| Git 权限 | [branch / commit / push / MR / PR] |

主机、账号、容器、Pod、Namespace、路径、分支、commit、镜像和命令必须来自用户或现场只读核验，不得猜测。历史值只放到历史记录，不与当前权威值并列。

## 权威关系

1. 本地源码是正式代码的第一事实源，也是唯一正式 Git 历史。
2. 正式源码默认只在本地修改，再按最小范围单向同步到远端。
3. 远端执行工作区只负责编译、运行、Profile、训练和测试，不承担正式 Git 管理。
4. 代码托管平台与远端执行工作区是不同目标；push 只从本地 Git 发起。
5. Git 记录代码变化；任务记录说明原因、验证和保留/继续/回退决策。
6. 项目当前规则或用户本轮指令与本文件冲突时，先报告冲突，不自行选择。

## 仓库组织

- [说明单仓库，或外层工作区仓库与内层源码仓库]
- 外层记录引用内层源码 commit；外层 commit 不代表包含被忽略的内层源码修改。
- 任务默认使用本地任务分支，不直接修改公共主分支；分支操作仍受 Git 权限约束。

## 开始任务前

1. 确认本地根目录、仓库根、当前分支、HEAD 和工作树状态。
2. 区分项目既有修改、本次任务修改和生成产物。
3. 确认远端主机、运行单元、同步路径、运行路径、镜像和关键依赖。
4. 声明实验 ID、证据、假设、修改范围、风险和验证上限。

## 本地修改和 Checkpoint

正式源码只在本地修改。修改前说明：

- 实验 ID
- 当前问题与已有证据
- 当前假设
- 计划修改文件和 symbols
- 选择这些位置的原因
- 预期作用与风险
- 验证计划及上限

修改后先查看整个工作树，再只 Review 本次文件：

```bash
git status --short
git diff --check -- [本次文件...]
git diff --stat -- [本次文件...]
git diff -- [本次文件...]
```

Checkpoint 汇报实际修改文件/symbols、每处修改及原因、与计划的差异、本地检查、未验证内容和待同步文件。Checkpoint 不等于必须 commit。

在逻辑实验完成、假设变化、准备扩大范围、准备同步/高成本测试/commit/交接，或 diff 难以一次 Review 时形成 Checkpoint。

## 本地到远端同步

1. 只把已 Review 文件写入相对于本地根目录的同步清单。
2. 使用 `rsync --dry-run --itemize-changes --files-from` 或等价机制预览。
3. 确认预览未超出允许范围后才正式同步。
4. 不同步 `.git/`、凭据、数据、模型、checkpoint、日志、缓存或构建产物。
5. 默认不用删除参数或整目录强制覆盖。
6. 远端存在来源不明的源码差异时停止，不直接覆盖。
7. 同步后用再次 dry-run、关键文件 SHA256 或部署 manifest 核验一致性。

远端验证必须关联：实验 ID + 本地基线 commit + 同步文件清单。高成本测试还要记录同步文件哈希或部署 manifest。

## 远端执行和证据

测试前重新确认实际主机、容器/Pod、Namespace、镜像、运行路径、GPU 和关键依赖。记录命令、退出码、日志、性能/精度/正确性结果，以及已执行、已验证和未执行项。

进程启动、GPU 占用、输出目录生成、forward 成功或单步完成不代表完整成功。正式训练、多机多卡、全卡压力、长时间任务或扩大机器/数据范围必须另获授权。

## 决策与 Git

- 保留：清理临时代码；最终代码变化后重新同步和验证；Review 最终 diff；经授权 commit。
- 继续：记录新证据并更新假设，保持“仍在实验”状态。
- 回退：保存必要失败证据，只回退本次实验，不破坏既有修改；不使用未经核对的 `git reset --hard`。

只暂存明确文件，默认不使用 `git add .` 或 `git add -A`。commit message 说明 Problem、Change、Why 和 Remote validation。branch、commit、push、MR/PR 受项目权限约束。

## 远端临时修改

只有远端工具或环境限制迫使最小诊断时才可临时修改：先声明原因和范围，保存前后 diff/补丁，将有效修改带回本地重新应用和 Review，再由本地同步并验证。远端不得长期领先，也不得与本地同时修改同一文件。

## 停止条件

身份或路径不一致、修改来源不明、同步越界、需要删除未知文件、需要扩大资源/范围、敏感或大型产物可能入 Git、关键环境/接口改动未授权，或者测试失败原因不明时，停止并报告观察、影响、已完成/未完成项、所需确认和安全下一步。

## 交接要求

任务结束时使用本项目的交接模板，明确区分已修改、已同步、已执行、已验证和仍待确认。
```
